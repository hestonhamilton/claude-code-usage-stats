## Reference: how Anthropic exposes plan-usage data (verified 2026-07-02)
Three surfaces exist; **none gives a queryable *history* of the subscription
5h/7d windows.**

1. **Admin Usage & Cost API** — `GET /v1/organizations/usage_report/messages`,
   `/v1/organizations/cost_report`. Real, historical, **backfillable** (1m/1h/1d
   buckets). BUT: needs an **Admin API key** (Console/org), and reports
   **pay-per-token API usage**, NOT the Max5 *subscription*. Claude Code on a
   subscription runs via OAuth, billed as a flat plan, not through API org
   billing — so this data set does not contain our usage and has no plan-window
   %. Not usable here.
2. **`anthropic-ratelimit-unified-*` response headers** — on **Max plans, every
   inference response** carries `anthropic-ratelimit-unified-5h-utilization` /
   `-7d-utilization` (+ `-status`, `-reset`, `-representative-claim`). This is
   the *actual source* the Claude Code statusline reads and tees into
   `rate_limits` → our `account_timeline`. Point-in-time only; Anthropic keeps
   no queryable history of past windows.
3. **Transcripts** — carry per-message `usage` tokens + `timestamp` only; **no**
   `rate_limits` field (confirmed: 0 structured records across staging).

**Conclusion:** the real recorded % only accrues going forward, from either the
statusline tee OR a header-reading poller (below). No source backfills the true
number. But an **estimate is reconstructable** — see below.

### Calibration acquisition — two routes to live anchors
- **Statusline tee** (`scripts/setup-statusline.sh`) — the sanctioned path;
  fills `account_timeline` as Claude Code renders.
- **OAuth-header poller** (alternative, faster to a calibration set) — make a
  trivial authenticated `/v1/messages` call with the subscription token
  (`ant auth print-credentials --access-token`; OAuth goes on
  `Authorization: Bearer` + header `anthropic-beta: oauth-2025-04-20`) and read
  `anthropic-ratelimit-unified-5h-utilization` from the response headers. Same
  live-only data, no Claude Code dependency; spends a sliver of quota per poll.
  Either way, write readings into `account_timeline` (window, used_percentage,
  resets_at, ts).

## Estimated historical utilization (the backfill)
Reconstruct a per-era utilization curve from data already in the `events` table
(`ts`, token columns, `cost_usd`, back to 2026-03-26).

**Method:**
1. **Roll the window** over historical events per era: for each sample point (or
   each block), sum usage in the trailing 5h and trailing 7d. Weight by
   **`cost_usd`, not raw tokens** — the unified limiter weights Opus far heavier
   than Haiku and discounts cache reads, and `cost_usd` already encodes those
   model/cache differences, so cost-weighted usage tracks true utilization much
   better than a token count.
2. **Calibrate the ceiling per era from live anchors:** each captured
   `used_percentage` reading + our cost-weighted usage in that same window gives
   `ceiling = usage / (pct/100)`; average several readings to pin the ceiling
   (and sanity-check the weighting) **for that era's plan**.
3. **Apply the calibrated ceiling backward** over the rolled series → estimated
   utilization curve, peak-per-window, and count of windows that hit the
   ceiling — per era.

**Per-era ceilings (why the split matters):** Pro (Mar 24→May 29) had a
different, smaller ceiling than Max5. One ceiling can't span both, so calibrate
+ estimate **each era independently**. The Pro era has no live anchor (we don't
hit Pro limits anymore) → its ceiling falls back to a fixed prior (community
estimate) and its estimate is lower-confidence; label accordingly.

**Error bars (be honest in the UI):**
- ~1% off-transcript same-account leak (accepted; numerator runs slightly low).
- Weighting is inferred from cost, not Anthropic's documented formula →
  absolute % can drift even where the *shape* is right.
- Pro-era ceiling is a prior, not calibrated → mark low-confidence.
- Estimate is for *shape and magnitude* ("Max5 windows ran ~80% full through
  June; hit the ceiling X times"), NOT a to-the-point match of Anthropic's
  recorded %.

**Sequencing (nothing lost by waiting):** the historical `events` data doesn't
expire. Collect a calibration set of live anchors first (statusline or poller),
then backfill the estimate over the full history in one pass. Until anchors
exist, the estimate ceiling is a fixed prior only.

## Deliverables
1. Config: reuse `[[subscription.periods]]` as era boundaries (already exists).
   Optionally add an era-level `ceiling_cost_usd` override + `ceiling_source`
   (`calibrated` | `prior`) once calibration is computed.
2. Rollups (against `events`, era-aware, reuse `_filters`):
   - `calibrate_ceilings(conn, periods)` — from `account_timeline` anchors,
     solve per-era cost-unit ceiling; return `{era, ceiling, n_samples,
     source}`.
   - `estimated_utilization(conn, *, window, by, periods)` — rolling
     cost-weighted usage ÷ per-era ceiling → time series with `est_pct`,
     `is_estimated=True`, `era`, `confidence`.
3. Display: on `/trends` (or `/plan`), an **"estimated historical utilization
   (calibrated from N samples)"** chart, visually distinct from the real
   captured `used_percentage` — show sample count, per-era ceiling, and a
   low-confidence marker on the Pro era. Never render estimate and real % in the
   same series without a clear visual/label distinction.
4. Tests: seed `events` + `account_timeline` anchors; assert ceiling solve,
   rolling-window sums, per-era boundary handling, and that estimated rows carry
   `is_estimated`.
